# 04｜Agent Studio 与评测

依据：[现状E08、E09](01-current-state.md)。Studio、已发布Agent页面和Eval都有实现；本轮不把页面存在或旧候选单例运行等同于当前版本全流程通过。

## M05：Agent Studio 与已发布 Agent

### 用户与目标

Agent构建者希望把重复任务固化为可维护的配置；最终使用者希望得到与发布说明一致的能力。目标是让“编辑了什么、保存了什么、预览了什么、发布了什么”始终可区分。

主流程：创建Agent → 明确任务/输入/成功标准 → 配置模型、工具、知识和记忆 → 保存草稿 → 隔离预览 → 保存问题为用例 → 比较候选 → 发布固定版本 → 在已发布入口使用 → 查看反馈 → 更新或回滚。

| ID | 优先级/类型 | 需求与产品规则 | 可判定验收 |
| --- | --- | --- | --- |
| AG-01 | P1 验证 | Agent目录支持搜索、状态、所有者筛选；创建、编辑、归档和删除说明影响；缺配置可保存草稿但不得误发布 | 无名称/无有效模型等问题定位到字段；草稿可恢复；归档后使用入口状态一致；不把复制Agent等未实现功能默认纳入验收 |
| AG-02 | P1 补齐 | Instructions、任务目标、输入与成功标准帮助用户表达任务；配置项给出最小示例与有效值，不要求先懂schema | 新构建者可凭页面完成一个KB助手草稿；未保存修改、保存失败、冲突版本清楚；测试始终说明使用已保存还是未保存配置 |
| AG-03 | P0 验证 | 草稿修订、预览会话和发布版本绑定明确；修改配置后既有预览不被无提示替换 | 草稿r1预览过程中保存r2，运行中任务仍使用r1；新预览使用声明版本；发布后历史运行可还原版本与模型/工具/KB范围 |

| AG-06 | P1 补齐 | 发布前展示配置变化、能力/受众变化、验证结果和版本说明；默认关闭首次自动公开 | 有效配置缺失或所需验证失败时阻断发布；明确区分内部可用和公开入口；发布成功后可查看实际版本；重复点击不创建多个相同版本 |
| AG-07 | P1 验证 | 已发布页支持已声明的输入、附件、引用、反馈及错误提示；公开访问规则和发布权限一致 | 有权成员完成真实任务；匿名访问按配置允许或拒绝；停用/撤销后入口不可继续创建任务；公开会话与构建者私有会话隔离 |
| AG-08 | P1 补齐 | 版本列表、对比、回滚与分析能回答哪个版本造成问题；回滚只改变新任务使用的版本 | 从版本B回到A后新会话用A，运行中B任务不被偷偷改配置；历史版本和结果仍可查；没有可用旧版本时不显示可成功回滚 |

### 发布规则建议

基线采用“保存草稿 → 明确验证 → 人工发布”。仅改变外观文案的版本与改变工具、知识、权限的版本，其验证要求应不同，但不允许用文案分类绕过真实能力变化。首次公开、扩大受众或新增外发工具需要可见确认。

Eval自动阻断应在 EV-03/04/05 能提供可解释结果后启用；在此之前保持已有发布规则，并显式显示“尚未完成对应验证”，不新增一个永远无法解除的假门禁。具体发布条件由[决策D04](07-delivery-and-acceptance.md)冻结。

人工例外不得豁免配置有效性、身份/权限、明确副作用状态或受影响流程尚未关闭的P0。只有经定义为可例外的质量/性能目标，才允许负责人记录理由、适用受众、有效期和回退条件后有限发布；不修改历史评分，不把例外发布标成全部门禁通过。现有更严格规则继续保留。

## M06：Eval、Trace 与知识评测

### 用户与目标

构建者与质量负责人需要发现问题、复现问题，并判断候选是否值得替换当前版本。Eval不是把各种分数放在一张表，而是让用户能解释“哪个任务、在哪个版本、因为什么失败”。

主流程：导入样本或从Trace/知识QA提取 → 审核样本 → 固定数据集与候选配置 → 运行 → 区分执行故障与质量失败 → 比较 → 决定发布/不发布 → 后续反馈进入下一轮。

| ID | 优先级/类型 | 需求与产品规则 | 可判定验收 |
| --- | --- | --- | --- |
| EV-01 | P1 补齐 | 数据集/用例支持导入、编辑、版本和来源；明确输入、期望、评判方式、用途及敏感性；自动生成先进入待审核 | 格式错误定位到行/字段；重复样本有处理选项；编辑不改变旧试验含义；自动生成不自动打上人工审核标识 |
| EV-02 | P1 验证 | 明确区分“运行真实候选”与“重新评分已有Trace”；展示实际候选、模型、数据集、采样及预算 | 两种模式的成本提示、输入和结果来源不同；重评分不伪造新执行；开始前可见配置，运行后可回查相同配置 |
| EV-03 | P0 验证 | 任务执行状态、样本质量、发布gate三层分别展示；失败、取消、无效、未评分和跳过不能算零分正常结果 | provider故障、裁判故障、输出截断、无答案各有分类；没有有效样本不显示100%；分母与剔除原因可查；成本未知不写实际0 |
| EV-04 | P1 补齐 | 比较固定基线与候选，展示新增通过、退化、相同失败、成本/延迟变化及证据不足；不只展示总分 | 采样或数据版本变化时提示不可直接归因；相同case可逐项对照；重复attempt不冒充独立样本；缺指纹时不给“已证明更优”结论 |
| EV-05 | P1 补齐 | 评分与成功标准对应实际任务结果；文件、引用、工具效果使用可核对结果，语言模型评分作补充 | 模型说“已生成”但无文件应失败；引用不存在应失败；合法拒绝无答案任务按既定期望判断；评分规则变更有版本 |
| EV-06 | P0 验证 | 长评测可离开页面、取消、重开、定位失败项；重试明确是否重跑模型及可能费用 | 重启后任务不丢；取消停止新增case并说明已运行部分；只重试选定失败样本产生独立attempt；未确认副作用不自动重放 |
| EV-07 | P1 补齐 | Trace页面关联Agent/会话/知识/工具/模型/费用，默认展示安全摘要，可复制脱敏诊断引用 | 普通用户不能读取他人Trace；从助手或任务入口打开对应对象；保留关联而不导出凭据、隐藏推理或未经允许的私有资料 |
| EV-08 | P1 补齐 | 知识召回测试、知识QA和通用Eval互相引用样本与结果；明确哪一处拥有标签与版本 | 同一问题的标签只在权威处编辑；修改后生成新版本，旧对比仍可复现；从KB结果进入Eval再返回不丢上下文 |

### 最小可交付例子

构建一个使用合成知识库的内部Agent。用例包含正确事实、无答案、权限撤销、工具拒绝和一次可恢复失败。候选A和B都跑同一组固定用例；对比页能指出真实退化，发布页保留所选版本及验证依据。此流程通过才证明Studio与Eval衔接完成。

这组用例是产品验收样本，不足以证明普遍模型质量、业务SLA或统计显著提升。正式质量阈值需根据目标任务与样本规模另行固定，不直接继承历史单样本分数。

## 3. 依赖和首轮边界

AG-03/04依赖MO-01/02有效模型配置、TL-01有效工具、KNO-05授权。AG-05复用AS-02/03和TL-02/03；AG-09依赖EV-01/07。公开发布不是“保存草稿”的隐含副作用。

不新增自动学习路由、自动无人工发布或新的第三方benchmark执行平台。先完善已有预览、发布、比较和反馈操作。
