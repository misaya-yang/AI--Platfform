# Phase Report Template

**Phase:** Fill with phase ID and phase name.

**Status:** Use one of: passed, blocked, partial, waived.

**Date:** Fill with execution date.

---

## Summary

State what changed or what was discovered.

## Plan Followed

Link or summarize the implementation plan used before edits.

## Files Changed

List files changed and why.

## Validation Evidence

| Gate | Command or Check | Result | Notes |
| --- | --- | --- | --- |
| Validation | command/check | result | notes |
| Regression | command/check | result | notes |
| Browser/Runtime | command/check | result | notes |
| Compliance | command/check | result | notes |
| Acceptance | command/check | result | notes |

## Feature Oracle Updates

| Feature ID | Old Status | New Status | Evidence |
| --- | --- | --- | --- |
| feature-id | old-status | new-status | evidence path or command |

## Progress Log Update

Summarize the entry appended to `progress-log.md`, including clean-state or blocker status.

## Screenshots, Logs, or Eval Tables

Link screenshots, logs, traces, golden-question tables, migration notes, or other durable evidence.

## Blockers and Deviations

Document blockers, skipped checks, user waivers, or expanded edit boundaries.

## Handoff Notes

State whether dependent phases may proceed and what the next agent must know.
